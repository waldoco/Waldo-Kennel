# Stage 3 S3.4 narrowed candidate handoff

## Decision

Complete and review the owner-proof kernel plus authenticated routine-proof minting as one candidate. Do not invent post-pair command ingress inside the frozen S3.3 pairing transport. Do not trust request-provided native confirmation references.

## Owner-proof mint path

1. An authenticated local owner client computes the digest of the exact command bytes and supplies mission, target identity, current target/question generation, and a routine class.
2. The loopback-only owner-command route authenticates the `KennelOwner` token.
3. The route obtains app-run identity from the typed authentication result. There is no request `appRunId`.
4. Unknown fields and material classes are rejected. The daemon generates the proof ID and fixes expiry at two minutes.
5. The proof kernel stores only the one-way bearer verifier and immutable public tuple. It returns the raw bearer once to the authenticated caller.
6. Verification compares every field and atomically consumes one winner. Replay and concurrent losers fail closed.

## Closed request fields

`missionId`, `contentDigest`, typed versioned `target`, and `class`.

The route rejects request-controlled app-run ID, proof ID, expiry, confirmation reference, verifier, and bearer. Material classes `replace`, `approval`, and `accept` are rejected at this route rather than accepting an unvalidated confirmation string.

## Explicitly out of scope

- post-pair adapter command ingress;
- changes to S3.3 `request_challenge` or `prove` RPCs;
- S3.1 transport bearer authentication for command ingress;
- governed command/control, replacement, approval, or Acceptance call-site wiring;
- dual authority references on those durable records;
- crash-after-proof-consume reconciliation;
- native confirmation UI or daemon confirmation validation;
- macOS protected transport or native confirmation proof.

The design packet for these items is `docs/handoffs/2026-09-17-stage-3-post-pair-command-ingress-design.md`.


## Post-approval target amendment

Migration 0148 replaces the lossy proof target ID/integer generation with the digest of a closed versioned target payload. It also introduces durable answer-question and current governed Chat target rows. The Chat target binds session, controller generation, expected plan revision, and capability fingerprint and is updated atomically with the session generation fence. See the ingress implementation handoff for race evidence and migration impact.
