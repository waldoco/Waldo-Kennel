## Round 3 (current-Contract fence for every Plan append)

- HIGH (authority-integrity race): the Contract could advance between the pre-evaluation recheck (`interactive_planning.go:483-502`) and `AppendPlanRevision` (`:668-734`), and the reviewer's fix requirement was an atomic current-Contract predicate enforced in the same transaction as the append. Root-cause split: the interactive path was already fenced - the `plan_revisions_planning_source_guard` trigger (0133/0157/db.go) joins `outcomes` and aborts when `o.current_revision_number <> s.contract_revision_number`; `TestPlanningSessionStore_RejectsPlanWhenContractChangesBeforeAtomicFinalize` already proved it. The real hole was the sessionless one-shot lane: `plan.go` calls `AppendPlanRevision` with no planning session, the source-guard `WHEN` clause skips it, and a stale Plan could bind a superseded Contract.
- Fix: migration 0158 installs a universal `plan_revisions_current_contract_guard` trigger (`BEFORE INSERT ON plan_revisions`) that aborts ("plan revision must bind the current Contract revision") whenever `NEW.contract_revision_number <> outcomes.current_revision_number`, with no session exemption - the predicate runs in the append transaction itself. `reconcilePlanningPlanImmutability` drops/recreates it alongside `plan_revisions_immutable_update` (degraded profiles, RENAME re-parse discipline); `preparePlanCurrentContractGuardMigration` follows the burned-ledger pattern of 0133/0157. `store/outcome_plan_store.go` maps the abort to `ports.PlanContractStaleError`; the interactive finalize path folds it into its supersede+`PLANNING_CONTRACT_STALE` reconcile; `ProposePlan` maps it to a `PLANNING_CONTRACT_STALE` conflict telling the caller to reload and propose again. Registered in `migrate_burned_versions_test.go` (158) and the trigger-presence list in `migrate_outcome_attempt_test.go`.
- Race tests (revise Contract inside the evaluation's inventory snapshot): `TestInteractivePlanning_ContractAdvanceDuringEvaluationPersistsNoPlan` proves the existing fence - `PLANNING_CONTRACT_STALE`, session superseded, no Plan; `TestProposePlan_ContractAdvanceDuringEvaluationPersistsNoPlan` proves the new universal guard on the one-shot lane - `PLANNING_CONTRACT_STALE`, no Plan; `TestPlanStore_CurrentContractGuardRejectsSessionlessStaleBinding` pins the store contract (current binding accepted, stale sessionless binding rejected atomically, no plan survives).
