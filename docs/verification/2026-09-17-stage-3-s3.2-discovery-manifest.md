## Implemented boundary

- Read-only Codex installation discovery resolves a canonical executable, hashes the opened regular file, records normalized installed version and conservative source provenance, and calls the existing live app-server protocol provenance seam under a timeout.
- A content-addressed adapter manifest declares the adapter artifact digest, closed S3.1 transport classes, strict numeric compatibility bounds and accepted protocol fingerprints.
- Classification is deterministic and fail-closed: invalid manifest, digest tamper, unsupported version, protocol drift, required capability missing, optional degradation, or known compatible.
- Supplied local adapter artifacts are streamed and hashed with cancellation. Older supplied versions classify as rollback. No code downloads, installs, replaces, rolls back or guesses.
- Provenance and manifest verification grant no transport or owner authority. S3.2 does not call the S3.1 issuance/rotation/revocation APIs.

## Tests

Focused fixtures cover manifest canonicalization/tamper, malformed versions, oldest/current/latest bounds, protocol drift precedence, required/optional capability loss, supplied artifact digest/rollback/cancellation, canonical symlink resolution, regular-file identity, normalized Codex version, protocol timeout, deterministic clock and missing identity.

Credential stores are not accepted as inputs and are never opened by the discovery implementation. The only subprocess is the discovered executable with `--version`; the protocol probe is the existing read-only provenance interface.

## Explicitly unclaimed

- No network/cloud-endpoint discovery is implemented in this Codex-first local slice.
- No adapter download, install, upgrade, rollback execution or presentation UX is implemented; only supplied-artifact verification/staging classification is present.
- No real macOS installation was inspected in this Linux workspace.
- No pairing, owner proof, owner command, reconnect, UI or multi-provider behavior is included.
