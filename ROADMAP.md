# Kennel roadmap

Current implementation order: [persistent-session execution map](docs/roadmap/persistent-session-execution-map.md).

## R1. One dependable persistent Codex Outcome loop

Freeze architecture; prove native app-server persistence; unify the session controller; extend S1; cut over new Attempts; add nonterminal attention, bounded Mission Supervisor intelligence, MissionProjection, UI integration, and one serial packaged proof.

## R2. Native-harness depth and safe parallelism

After R1 evidence, run independent ready WorkUnits concurrently in isolated worktrees, observe controlled native subagents, and deepen Codex-native capabilities without creating a second runtime.

## R3. Portable context and learning

Improve manifest selection, project facts, retained decisions, and measured budget advice. Share explicit artifacts and provenance, not transcripts.

## R4. Other providers and wider surfaces

Add provider support from the protocol needs proven by Codex. Extend the same authority and projection to team and wider Waldo surfaces without forking the product model.

## Removal rule

Remove compatibility code only after observed migration, named rollback evidence, and independent review. Never delete migrations or rewrite historical records to resemble vNext.
